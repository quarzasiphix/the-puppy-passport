# Frontend merge/cherry-pick conflict plan

Per-file guidance for integrating this branch onto `main` via the individually-cherry-picked
sequence in `docs/FRONTEND_INTEGRATION_REPORT.md` — not a merge or rebase, which this branch never
performs. This file exists so conflict resolution during that cherry-pick is a lookup, not a
rediscovery.

## Files this branch owns outright (frontend should win on any textual conflict)

All `src/routes/_public.*`, all `src/routes/dashboard.buyer.*`, `src/components/cards.tsx`,
`src/components/site-chrome.tsx`, `src/components/notification-bell.tsx`,
`src/components/public/*` (new), `src/components/marketplace/animal-image.tsx` (new),
`src/lib/presentation/*` (new), `src/lib/org-routing.ts` (new), `src/lib/saved-animal-classification.ts`
(new), `src/lib/i18n/*`, `tests/unit/*`, `src/styles.css`, all `docs/FRONTEND_*.md`,
`docs/MARKETPLACE_UX_AUDIT.md`. These are exclusively frontend-owned presentation/logic; if `main`
happens to have touched the same line ranges (unlikely — see the backend file list in
`FRONTEND_INTEGRATION_REPORT.md`, which doesn't overlap), the frontend version is correct because it
reflects a real, checked-in bug fix, not a stylistic preference.

## Files requiring a real combined read before accepting either side

- **`src/lib/queries/marketplace.ts`** — this branch's only changes are: (1) the `getKennelBySlug`
  scoping fix (adds `.eq("verification_status", "approved").eq("is_public", true).maybeSingle()`,
  mirroring the pre-existing `getFoundationBySlug`), and the much larger set of foundation/batch-
  count/N+1 fixes from earlier in the branch. If `main`'s backend session changed the `organisations`
  or `animals` table shape (new columns, renamed columns), the select-string literals in this file
  (`orgSelect`, `animalSelect`, `adoptionSelect`, `litterSelect`) need re-checking against the new
  schema — a silent runtime failure, not a git conflict, so this needs a manual smoke-test after
  cherry-pick, not just a clean `git cherry-pick` exit code.
- **`src/lib/queries/buyer-activity.ts`, `src/lib/queries/profile.ts`, `src/lib/queries/community.ts`**
  — same category as above: frontend-owned files that read tables the backend agent may have altered
  the shape of. Re-run `npx tsc --noEmit` immediately after cherry-picking these — a schema change
  would surface as a type error against `src/lib/supabase/types.ts` (backend-owned, regenerated by
  the backend session), not a merge conflict.
- **`package.json`** — this branch added exactly two scripts (`test:unit`, `i18n:check|`) and zero
  dependency changes. If the backend session added its own scripts to the same file, git will likely
  auto-merge (different lines in the `"scripts"` object) but deserves a glance to confirm no script
  name collision.
- **`src/routeTree.gen.ts`** — **never hand-resolve this file.** It's fully generated by the
  TanStack Router dev server/build from the `src/routes/*` file set. If a cherry-pick reports a
  conflict here, discard whatever's in the commit and regenerate it fresh (`npm run dev` once, or
  `npm run build`) after all real route files are in place.

## Files that should take `main`'s version outright (never this branch's)

Every explicitly backend-owned path this branch was instructed never to touch, and never did:
`supabase/**`, `tests/db/**`, `.github/workflows/**`, `src/lib/supabase/types.ts`,
`src/lib/queries/transport.ts`, `src/lib/queries/operations.ts`, `src/lib/queries/driver.ts`,
`src/lib/queries/admin.ts`, every operations/driver/admin/internal-foundation route,
`src/components/transport-document-checklist.tsx`, `docs/BACKEND_*`, `docs/DATABASE_TESTING.md`,
`docs/DOMAIN_MODEL.md`, `docs/FINALISATION_REPORT.md`, `docs/IMPLEMENTATION_PLAN.md`,
`docs/TRANSPORT_INTEGRATION_CONTRACT.md`. A cherry-pick of this branch's commits should never touch
these paths at all (verified via `git diff --name-only` after every commit this session) — if one
somehow shows a conflict, that itself is the bug to investigate, not something to resolve casually.

## Why conflict risk is low in practice

This branch's own commit history never touched a single file in the backend-owned list above (see
the same verification repeated at every phase boundary in `docs/MARKETPLACE_UX_AUDIT.md` and
`docs/FRONTEND_AUTONOMOUS_PROGRESS.md`). The two codebases only meet at read boundaries — this
branch's query files `SELECT` from tables the backend agent's migrations define — which is a
schema-compatibility risk (caught by `tsc`/build/manual smoke test), not a textual merge-conflict
risk (caught by git).

## Recommended post-cherry-pick verification (in addition to `FRONTEND_INTEGRATION_REPORT.md`'s list)

1. `npx tsc --noEmit` — catches any select-string/schema mismatch immediately.
2. `npm run db:reset && npm run test:db` — the backend session's own regression suite, now exercised
   against the newly-arrived frontend query code.
3. `npm run build` then a manual click-through of at least: homepage, `/find-a-dog`, a puppy detail
   page, `/breeders/$slug`, `/foundations/$slug`, `/adoptions/$id`, `/community`,
   `/dashboard/buyer` — the highest-traffic paths this branch touched most heavily.
