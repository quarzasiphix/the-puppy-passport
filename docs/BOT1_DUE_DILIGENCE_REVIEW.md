# Bot 1 — Due-Diligence Review (Finalisation Pass)

One row per acquisition-relevant claim a buyer's technical diligence would need to check. This is a
narrower, more targeted pass than a full standalone due-diligence audit (B1-101 through B1-118 of
the task's 130 stages were not exhaustively worked this pass — see the main report's Limitations
section for exactly which stages remain) — it reuses and re-verifies the two prior passes'
conclusions rather than re-deriving them, and adds this pass's own delta findings.

A buyer should treat this subsystem as not yet meeting its own documented security bar, notwithstanding a real, correctly-built RPC layer sitting on top of the gap. |

**Overall due-diligence verdict**: the codebase's engineering discipline (test culture, migration
hygiene, actor-attribution awareness, willingness to self-audit and document limitations honestly)
is genuinely above-average and a real asset — but a buyer's diligence should not treat "an
independent audit was performed" or "extensive regression tests exist" as proxies for "the specific
findings were fixed." Three consecutive independent passes (original, remediation, this one) confirm
the same 4 High findings remain open with zero code change against them in over 6 weeks of
active, otherwise-substantial security work in the same repository — the risk is not that the team
can't fix these, it's that its own review process has a structural blind spot (RLS/grant surface
underneath an already-correct RPC) that has now independently produced the same miss more than once,
including in Bot 2's own most recent self-audit this pass reviewed.
